結論

建立 → 上傳圖片 → 新增 / 排序 / 刪除品項 → 發佈 → 結束 → 重新開放 → 封存 → 取消封存，全程可用。發現 3 個缺陷已修正；另有數項 02 與實作不同，但實作與較新的 04 契約一致，列為「02 文件待更新」（Q6）。

驗證方式

API 探測所有狀態轉換組合、發佈檢查（無品項、驚喜模式缺活動日）、QTY_BELOW_CLAIMED、ITEM_HAS_CLAIMS、排序（完整 / 部分 id）、closed 後的各種編輯、STALE_VERSION 樂觀鎖。

自動化（新增）後端 apps/api/tests/wishlist_lifecycle.rs（2 個測試）；E2E apps/web/e2e/flow-f08-list-lifecycle.spec.ts（2 個測試，真實 API）。
既有自動化wishlist_items.rs、wishlist_guards.rs、closes_at.rs、uploads.rs、hardening.rs、crowdfund_owner.rs；E2E creator-journey、dashboard。

缺陷與處置

B6 · 已結束 / 封存的清單仍可刪除品項 已修正

重現：清單 closed 後，PATCH /items/{id}、新增、排序都回 409 WISHLIST_CLOSED，唯獨 DELETE /items/{id} 回 204，品項從已結束的公開頁消失。違反 F8「closed：不可增刪品項」與 04「closed / archived 後修改品項回 WISHLIST_CLOSED」。前端已隱藏刪除鈕，所以只能經 API 觸發。

修正：apps/api/src/wishlists.rs item_delete 在取得清單列鎖之後讀狀態，closed / archived 回 409。沿用既有 FOR UPDATE 語句、未改鎖序（不需新增 mutant）。closed_and_archived_freeze_items 已確認修正前失敗。

B7 · 封存清單的編輯頁仍顯示設定表單與「分享」 已修正

重現：封存後開 /lists/{id}/edit，「清單設定」可展開並儲存，結果是紅字「清單已關閉或封存，無法修改。」加上無用的「重試」；「分享」可開分享框並複製連結，但連結是 404。

修正：edit.vue 在 archived 時不顯示設定區塊與分享鈕，只留「取消封存」。e2e flow-f08 #2 覆蓋。

B8 · 連按排序可能存成與畫面不同的順序 已修正

全套 E2E 並行執行時，新排序測試偶發失敗，追查後確認：每按一次「上移 / 下移」就各自送出一個 POST /items/reorder（帶當下完整順序），請求並行；在網路 / 伺服器較忙時，先送出的可能較晚寫入，後端留下舊順序，重整後畫面「跳回去」。

修正：edit.vue 的 move() 改為佇列依序送出。E2E 等兩次回應都完成才重整，連跑 5 次皆通過。

裝置與解析度

新增的 flow-* E2E 已加入 mobile（iPhone 13，390×664、觸控）與 tablet（iPad gen 7，810×1080）兩個 project，三種裝置皆通過。另以 Playwright 在 320 寬、iPhone 13、iPad Mini 直式、iPad 橫式、1280、1920 六種解析度掃描 /lists/new、/lists/{id}/edit、/dashboard：檢查水平捲動與超出視窗的元素（皆無），並逐張看截圖。
