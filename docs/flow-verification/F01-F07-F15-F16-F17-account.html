結論

驗證方式

缺陷與處置

B12 · 匯出被限制時，錯誤訊息出現在頁面最上方，按鈕附近沒有反應 已修正

設定頁的匯出按鈕在頁面下半部，錯誤（如「匯出每日最多 3 次」）寫進頁首的共用錯誤列；在手機與一般桌機上都不在視窗內，使用者按了沒反應會一直重按。E2E 以 toBeInViewport 抓到（視窗內比例 0）。改為匯出區塊自己的錯誤訊息，顯示在按鈕下方。

B13 · 處理中的現金退款 / 拒付欠款 / 凍結錢包不會擋刪帳號 已修正

02 F17 / F18：未結案現金退款、wallet_debts open 須回 409。實作只檢查 pledged 與餘額。實際情境：

  • 申請全額現金退款後點數已先扣，餘額 0 → 可刪帳號；之後營運拒絕退款，點數退回一個已匿名、無法登入的錢包。
  • 拒付敗訴後餘額已扣光、欠款 open → 可刪帳號，欠款留在匿名帳號上無法追討。
  • 爭議中（錢包凍結）餘額 0 → 可刪帳號，之後判定敗訴同上。

修正：apps/api/src/account.rs 在既有錢包列鎖之後加查三項，任一成立回 409 ACCOUNT_HAS_POINTS（沿用既有錯誤碼，前端已處理）並說明需聯絡客服結案。未改任何鎖語句。account_deletion_wallet.rs 兩個測試已確認修正前失敗。

B14 · 重送相同的下架 / 恢復會重寫時間並重複寫稽核 已修正

F15「PATCH moderation 以目標狀態為準，重送回 200，不重複寫 audit」。實作每次都更新 moderated_at、寫一筆 wishlist.moderate、推 SSE、清 CDN；營運連點就會產生多筆稽核，且下架時間被往後推。改為狀態與原因都沒變時不更新、直接回目前資料；改原因仍視為變更並稽核。moderation_idempotent.rs 覆蓋。
