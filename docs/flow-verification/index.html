每條流程的作法

  1. 對照 02 的規則、錯誤碼、交易邊界，列出可驗證項目，並對應既有測試。
  2. API 探測：以腳本逐條打規則（含邊界值、非法轉換、權限）。
  3. Playwright 手動探索：playwright-cli 以各角色實際操作 UI（連點、返回、重整、語系、窄螢幕）。
  4. 為缺口補自動化：後端 apps/api/tests/*.rs、E2E apps/web/e2e/flow-*.spec.ts（真實 API）。修正的缺陷皆先確認測試在修正前會失敗。
  5. 裝置：flow-* E2E 同時跑桌機、手機（iPhone 13）、平板（iPad）三個 project；另以 Playwright 掃 320 / 390 / iPad 直橫 / 1280 / 1920 六種解析度，檢查溢出並看截圖。
  6. 處置：小範圍且規格明確 → 直接修；跨模組或要選方案 → GitHub issue（詳述重現與建議）；規格與實作衝突或需產品判斷 → 待決事項。
