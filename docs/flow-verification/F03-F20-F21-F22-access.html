結論

存取控制是本波重點，可見性矩陣、受限路徑、好友關係全數符合規格，沒有發現資料外洩：公開路徑不讀 cookie、受限內容 no-store、私人清單與不存在不可區分、捐助 / SSE / 檢舉都經 check_wishlist、解除好友與收緊可見度立即生效。發現 2 個缺陷已修正，3 項待決（Q7–Q9）。

驗證方式

API 探測4 種可見性 × 5 種身分（匿名 / 擁有者 / 好友 / 非好友 / 摯友）的公開與受限路徑、Cache-Control、Set-Cookie；受限清單上的捐助、SSE、檢舉；收緊可見度、解除好友；探索頁列入條件；好友申請 / 接受 / 婉拒 / 互加 / 邀請連結；handle 規則；個人頁依 relation 的內容。
Playwright 手動探索好友 / 匿名 / 非好友 / 擁有者開僅好友清單時，以 MutationObserver 記錄門檻文案是否曾出現在畫面上（hydrate 閃爍）；SSR 狀態碼與 OG meta（含 FB / LINE UA）；SSE 標頭、心跳、每 IP 上限；驚喜清單在擁有者 / 訪客端的呈現。
裝置flow-f21 / flow-f22 與既有 social.spec 在桌機、iPhone 13、iPad 三個 project 共 21 個案例通過；另在 320 / iPhone 13 / iPad 直橫 / 1280 / 1920 掃描 /explore、/friends、/u/{handle}、/invite/{token}、門檻頁，無水平溢出並逐張看過截圖。
自動化（新增）E2E flow-f21-visibility.spec.ts（3 個）、flow-f22-profile.spec.ts（2 個），皆真實 API、三種裝置。
既有自動化後端 visibility.rs、explore.rs、social.rs、profiles.rs、cdn_invalidation.rs、dashboard_privacy.rs、wishlist_events.rs；E2E social、errors、guest-journey、live-updates。

缺陷與處置

B10 · 未登入看到的門檻頁沒有顯示清單建立者 已修正

F21：403 回應帶 owner「供門檻頁顯示由誰建立」。實作只在 FRIENDS_ONLY 時顯示，未登入（LOGIN_REQUIRED）與 NOT_ALLOWED 時訪客不知道是誰的清單、是否值得登入。改為回應有 owner 就顯示（pages/s/[slug].vue）；flow-f21 #2 覆蓋。

B11 · 個人頁沒有 noindex 已修正

F22「個人頁一律 noindex」。/u/** 為 client 渲染（ssr: false），伺服器回的 HTML 殼沒有 robots meta，noindex 要等 JS 執行後才加上；不執行 JS 或先抓 HTML 的爬蟲看不到。改在 nuxt.config.ts routeRules 對 /u/** 回 X-Robots-Tag: noindex；flow-f22 #1 驗證回應標頭。注意：已在本機 node 預設驗證，Cloudflare Pages 上線後建議 curl -I https://wishly.tw/u/xxx 確認標頭仍在。

測試穩定性 · flow-f05 擁有者取消捐助偶發失敗 已修正

全套並行時偶發：進度頁因 SSE 重抓而重繪，第一次「取消捐助」若點在重繪中沒有跳出確認框，page.once('dialog') 的處理器會殘留到第二次，兩個處理器同時處理同一個對話框。改為每次點擊前等待該次對話框並處理；三種裝置 × 3 次、6 個 worker 並行共 27 次皆通過。這只處理了症狀；後續追到產品端的根因（進度頁重抓競態），見 F4/F5 報告 B15。

探索觀察（未列缺陷）

  • 受限清單的 SSR 回 HTTP 200（標題「需要權限才能查看」、noindex），02 寫「SSR 為 403」；client 端重抓後顯示正確內容或門檻，且 SSR body 不含門檻文案，對使用者無影響。
  • /s/{slug} 的 HTML 回應會帶 Set-Cookie: ws_locale（依 Accept-Language）；HTML 目前沒有 CDN 快取，不影響。若日後要快取分享頁 HTML，需先拿掉。
  • 品項全刪光的清單 OG 描述為「已完成 0%，還有 0 項等你捐助」，文案略怪（此清單也不會出現在探索頁）。
  • 320 寬時 /friends 的「name@example.com 或 @handle」佔位文字被截斷；個人頁捐助紀錄「送給 b ·」行尾多一個分隔點。
