## 1. 角色設定

同一份腳本以多個「人」（各自獨立的瀏覽器情境，cookie 互不相通）扮演：

| Persona | 情境 | 裝置 | 帳號怎麼來 | 負責的流程 |
|---|---|---|---|---|
| **阿姨**（主角） | 朋友在 LINE 群組貼了連結，她用 LINE 內建瀏覽器點開；沒有帳號；不熟 3C | 手機 390×844、UA 帶 `Line/14.5.0`、觸控 | **UI 註冊**（OTP 從 Mailpit 取） | 瀏覽 → 被要求登入 → 註冊 → 回原清單 → 認捐（數量、備註、匿名、可見度）→ 修改 → 冪等 → 我的送禮（延長、已購買、已送達、取消、逾期）→ 已結束清單 |
| **訪客 B** | 另一位朋友，單純看看、不登入；頁面一直開著 | 桌面 1280 | 不登入 | 瀏覽、SSE 即時更新觀察者、檢舉、探索、品牌、靈感 |
| **同事小陳／小林** | 同一個辦公室、同時收到連結、都想送最後一件 | 桌面 | 小陳 UI 登入、小林 API 註冊後帶 cookie | 搶最後一件、部分搶購（防超賣） |
| **阿明**（贊助大戶） | 想湊錢買大件的朋友 | 桌面 | API 註冊 | 眾籌：儲值（綠界替身）→ 錢包 → 贊助 → 撤回／轉投 → 現金退款；救災據點 |
| **小花／小草**（非好友） | 被分享「好友限定」清單的人 | 桌面 | API 註冊 | 好友限定清單的存取限制、好友邀請、邀請連結 |
| 受捐者「小愛」＋營運 | 前置準備，不是被測對象 | — | API | 建清單、結束清單、接受好友邀請、發點、下架（皆標為平台外動作） |

## 2. 目標

1. 收到連結的人**不註冊就能完整瀏覽**（含進度、品項、驚喜模式提示），按「我要送」才被要求登入，且登入／註冊後**回到同一份清單**（D50）。
2. 認捐流程對「不熟的人」夠簡單：數量選擇、備註、匿名／可見度、成功回饋、期限提示都看得懂。
3. **防超賣**與**冪等**：連點、重送、兩人同時搶、同一人雙開，都只成立一筆；輸的人要被清楚告知。
4. 事後可管理：我的送禮（改量、延長、標記、取消、逾期自動釋出）。
5. 各種「不能看／不能送」的狀態（結束、私人、好友限定、下架、暫停據點）有明確錯誤頁與正確 HTTP 狀態。
6. 心願眾籌：儲值 → 錢包 → 贊助 → 撤回／轉投 → 現金退款，金額與點數對得起來。
7. 周邊入口：探索、靈感、品牌館、救災據點、退訂、檢舉、即時更新。

## 4. 前置準備（平台外，不算被測）

- 受捐者「小愛」以 API 註冊並建立清單（標題都帶本次執行的 8 碼標記 `T`，避免和其他角色的資料混在一起）：
  - `main` 公開、顯示捐助者名字：奶瓶組×3、嬰兒帽×1、揹巾×2、圍兜×2、尿布×3
  - `surprise` 驚喜清單；`friends` 好友限定；`private` 私人；`closed`（之後由 API 結束）；`gone`（營運 API 下架）；`draft` 草稿；`empty` 上線但無品項；`race` 搶購專用
  - `cf` 眾籌清單（已填收件資訊）：嬰兒推車 300 點、搖籃 200 點、玩具車 150 點（各 7 天截止）＋ 奶粉×2（數量制）
- 營運帳號（`is_staff`，SQL 設定）：下架清單、人工發點、建立品牌與商品。
- 取 OTP：從 Mailpit 讀信（真人是看信箱）。
- 時間快轉：用 SQL 把某筆認捐的 `expires_at` 改成過去、把眾籌品項標成 `expired`（真實環境要等 5 分鐘一次的背景工作／期限）。
- 金流：在 UI 建立儲值單 → 以 `page.route` 攔截導向綠界的 POST → 用 `ecpayPaid()`（綠界替身）送簽章通知。
- 若被每 IP 限流擋住：`resetOtpLimits()` 清 `rate_limits` 的 `otp_*`（`registerApi` 內建，真實使用者不會同時從同一 IP 註冊這麼多帳號）。

### D-P1　捐助者頁面沒有帳號選單／登出／錢包入口（中）

- **重現**：註冊或登入後（如 D-08），停在 `/s/[slug]`；或前往 `/me/claims`、`/explore`、`/inspire`、`/brands`。找「登出」「我的點數」「儲值」「設定」。
- **預期**：已登入就看得到帳號選單（至少：我的送禮、我的點數、設定、登出），如創建者頁面的頭像選單。
- **實際**：頂部只有 `探索 靈感 品牌館 我的送禮` 與語系／主題（D-09 實測：分享頁與我的送禮頁的登出／`/me/wallet` 連結／帳號選單數量皆為 0）。登入狀態只能從按鈕文字（「我來送」）間接得知。到錢包只有兩條路：贊助失敗後 sheet 內的「查看我的點數」，或贊助成功後的「查看我的點數與贊助」；要登出只能手動輸入 `/settings`。`/me/wallet`、`/me/topup`、`/me/refund` 則是創建者外觀（`CreatorHeader`＋`UserMenu`），同一個人在兩種外觀間跳來跳去。
- **影響**：共用手機（阿姨用家人的手機）無法登出，帳號留在別人手上；想儲值的人要先試一次贊助失敗才找得到入口。
- **相關程式碼**：`apps/web/app/components/guest/GuestTop.vue:4`（導覽只有四個連結）；對照 `apps/web/app/components/creator/UserMenu.vue:28-41`（已有 點數／設定／登出）與 `apps/web/app/components/creator/Header.vue:23`。
- **建議修法**：`GuestTop` 在 `useAuth().user` 有值時渲染 `<CreatorUserMenu />`（分享頁 SSR 一律當未登入渲染，掛載後再出現，與「登入後來送」→「我來送」同一模式，不影響 CDN 快取）。
- **處置**：直接修（小改動）。

### D-P2　`/me/claims` 未登入沒有登入引導，文案過時（中低）

- **重現**：用沒登入的瀏覽器開 `/me/claims`（例如朋友傳來「去我的送禮看」的連結，或 session 過期後重開）。對照 `/me/wallet`、`/me/topup`、`/me/refund`。
- **預期**：行為一致——導去 `/login?redirect=/me/claims`，或至少有「登入」連結。
- **實際**：D-73：`/me/wallet`、`/me/topup`、`/me/refund` 都導向 `/login?redirect=…`；`/me/claims` 停在空狀態，內文是「你還沒有要送的禮物。收到朋友的清單連結後，登入會員就能認領…」＋「看不到之前以訪客身分認領的禮物？可能是在不同瀏覽器或 LINE 內建瀏覽器。留過 Email 的，可從確認信的『管理我的送禮』連結回來。」——沒有任何登入連結；而 D50 之後訪客已不能認捐，規格也明講「不再寄訪客確認信」（docs/03），這段說明對現在的使用者是誤導。
- **相關程式碼**：`apps/web/app/pages/me/claims.vue:27`（401 一律 `setGuestToken(null)` 並顯示 empty）、`:66-68`（empty1／empty2）；`apps/web/i18n/locales/zh-Hant/me.json:141-142`；對照 `apps/web/app/pages/me/wallet.vue:3`（`definePageMeta({ middleware: 'auth' })`）。
- **建議修法**：401 時 `navigateTo(loginUrl('/me/claims'))`（頁面其餘內容只對會員有意義）；刪除或改寫 empty2（僅對舊訪客權杖使用者保留，且只在偵測到舊 token 時顯示）。
- **處置**：直接修。

### D-P3　退訂頁文案與實際退訂內容不符（低）

- **建議修法**：`POST /unsubscribe` 回傳 `kind`，頁面依 kind 顯示（生日提醒／通知信）；或把文案改成通用的「退訂這類通知信」。順手確認 `u` 分支是否可移除。
- **處置**：直接修（文案層）。

### D-P4　搶輸時的提示只閃 1.2 秒（低）

- **重現**：D-20／D-21。兩人同時對最後一件按「確定要送」，輸的那位。

## 9. 其他觀察（非問題）

- **完成度**：分享頁頂部百分比是依「數量」加權（D-12：2 件 / 11 件 = 18%），「0 / 5 項」是已全數認領的品項數；品項卡的百分比是該品項自己的進度。
- **會員不寄認捐確認信**：阿姨實際收到的信只有註冊 OTP、清單結束提醒、逾期通知（D-74、D-29）；購買提醒已排程（認捐後 3 天、24 小時前，`notifications` 有 `claim.purchase_reminder`），與 docs/03「不再寄訪客確認信」一致。阿明儲值、贊助、申請退款都沒有信，只有「集資達標」（D-74）。
- **等待背景工作**：逾期釋放由每 5 分鐘一次的背景工作處理；本次改時間後約 2 分鐘內就被處理，結果正確（D-29：狀態 expired、`qty_claimed` 回補、收到「已超過購買期限」信）。
- **贊助超額在前端由瀏覽器原生驗證擋下**（`<input max>`，D-57），沒有頁內錯誤區塊；訊息語言跟瀏覽器語系走（本環境為英文 "Value must be less than or equal to 200."）。其他人先贊助時，開著的 sheet 會即時更新剩餘點數與上限（SSE）。API 超額回 `CROWDFUND_TARGET_EXCEEDED`。
- **好友限定清單的 SSR 回 200**（含「載入中」外殼）而不是 403，是程式內註明的刻意設計（client 帶憑證重抓才知道結果）；私人清單對非擁有者與不存在的 slug 同樣回 404，不洩漏存在。
- **驚喜清單**：捐助者可正常認捐；公開頁只顯示進度、不顯示捐助者（`claimers_visible=false`）。
